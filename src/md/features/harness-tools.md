# Harness tools

In a harness, ClankTalk can be the only tool, so the agent does all its work in scripts that the rules and the audit cover. Before, only pi did this (`pi.setActiveTools`). Claude Code had no way.

Code: the `clank-talk` plugin for Claude Code (`src/js/harnesses/claude-code/hooks/register.tsx`), `src/js/harnesses/pi-host.js`, `projectHarness` in `src/js/runtime.js`, `harnessToolAllowed` in `src/js/host.js`, and `clank-talk harness --json` in `bin/clank-talk.js`.

## Rules

- Approved (built, 2026-11-11): while ClankTalk is on, the Claude Code plugin blocks every tool except `clank_talk` (`mcp__<server>__clank_talk`), a built-in list that only talks to the person or plans (AskUserQuestion, TaskCreate, TaskGet, TaskList, TaskUpdate, TodoWrite, ToolSearch, EnterPlanMode, ExitPlanMode), and the tools that AGENTS.talk allows. The deny message tells the model to use a ClankTalk script, and names the AGENTS.talk line that allows the tool. Rejected: blocking only the tools that change or run things (Read and web tools skip the hidden-file rules and the taint record), and only Bash, Edit and Write.
- Approved (built, 2026-11-11): `require clank-talk`, at the top of AGENTS.talk, keeps ClankTalk on: `/clank-talk off` is refused. Rejected: `clank-talk on | off | required`, and `only clank-talk`. Any other `require` is still a policy line.
- Approved (built, 2026-11-11): `allow harness tools Read, Grep, 'mcp__github__*'`, at the top of AGENTS.talk, allows other tools by the harness's own names. In a name in quotes, `*` is any text. pi uses the same line: the allowed tools are active, beside `clank_talk`. Rejected: `allow tools` (close to `tool`), and `allow claude tools`.
- Approved (built, 2026-11-11): with no `require clank-talk`, ClankTalk is on in a project that has an AGENTS.talk, and off in one that has none. `/clank-talk on` and `/clank-talk off` change it for the current session only; nothing is kept, and each new session starts from AGENTS.talk again. Only the person's own Enter changes it (`origin.kind` is `composer`).
- Approved (built, 2026-11-11): `/clank-talk` with no argument prints a report in the transcript: on or off and why, the allowed and the blocked tools (built-in tools by name, MCP tools by server, as `mcp__idea__* (94)`), the names that AGENTS.talk allows, and AGENTS.talk errors. The model can read it; it holds nothing secret.
- Approved (built, 2026-11-11): the plugin reads the project's settings with `clank-talk harness --json` (`{ agentsTalk, required, allowed, errors }`), and reads them again when AGENTS.talk changes. If the command fails, a project with an AGENTS.talk stays on with no extra tools: the guard fails closed. A guard hook that fails also blocks the call.
- Proposed (built, 2026-11-11, not tried in a real pi): pi has the same rules and command. With ClankTalk on, pi's active tools are `clank_talk` and the tools that AGENTS.talk allows; `/clank-talk off` gives back the tools that pi had at the start of the session. `/clank-talk` with no argument shows the report with `ctx.ui.notify`. Before, pi was always ClankTalk-only, also with no AGENTS.talk. If pi cannot read AGENTS.talk, ClankTalk stays on with no other tools.
- Approved (built, 2026-11-11): while ClankTalk is on, each call of an allowed harness tool goes in the ClankTalk audit, as its own block: `== <time>  harness tool <name>  (session <s>) ==`, the input on one line (at most 300 characters), and the result size. `allow untrusted harness tools WebFetch, 'mcp__github__*'` also makes their results untrusted inputs, with the source `<tool> <input>`, so they taint the session. In Claude Code, `WebFetch` and `WebSearch` are always untrusted. Why: the human knows which tools bring outside text; this matches `untrusted tool` in AGENTS.talk. Rejected: taint for every allowed tool with a `trusted` opt-out (every Read would taint), and a guess from the tool name. Claude Code records through `clank-talk harness record` (JSON on stdin); pi records in its own process, on `tool_execution_end`. `clank_talk` itself and the built-in planning tools are not recorded here.
- Approved (built, 2026-11-11): the status line. The plugin writes the session's state to `.talk/harness/claude-code-<session id>.json` when the session starts and on `/clank-talk on|off`. `npx clank-talk status-line` reads Claude Code's statusLine JSON on stdin (`session_id`, `workspace.current_dir`), and prints `clank-talk: on, untainted` (or `off`, `tainted <n>`, `taint off`). With no file, it shows the default from AGENTS.talk; `require clank-talk` always shows on. A session id that is not a plain name is ignored. Why: the state lives in the plugin's memory, and a statusLine command cannot see it. Rejected: the plugin's own line under the prompt (`$.ui.status`): too loud. Limit: the files stay in `.talk/harness/`, one small file for each session.
- Limits: the record has no secret redaction, and no copy to the policy's `audit also to`, because the plugin and the command line do not see the policy. pi records on `tool_result`, which has `input` and `content` (pi docs, Events, read 2026-11-11 from github.com/earendil-works/pi); `tool_execution_end` has no input.
- Approved (built, 2026-11-11, release review for 0.1.3): while ClankTalk is on, an allowed write or edit tool is refused for `.talk/` (the audit, the taint store, the session state) and for `.talk` files (AGENTS.talk too): Claude Code `Write`, `Edit`, `MultiEdit`, `NotebookEdit`; pi `write`, `edit`; opencode the `edit` action. Why: a script cannot change them, and an allowed tool must not either, or it could approve its own untrusted inputs or remove `require clank-talk`. Limit: an allowed shell tool can still change them, so `allow harness tools Bash` (or `shell`) gives up this protection. A symbolic link into `.talk/` is not checked.
- Limit: the plugin only guards Claude Code. Without the plugin, Claude Code does not block other tools. A `claude --dangerously-skip-permissions` session still runs the plugin's hooks; this is not tested.
