# opencode plugin

ClankTalk as an opencode V2 server plugin, as for pi: the `clank_talk` tool runs in opencode's process, and the plugin guards the other tools.

Code: `src/js/harnesses/opencode/index.js` (the server part), `tui.js` (the TUI part), `state.js` (on or off for each session), `channel.js` (the RPC channel for `ask`). Tests: `test/opencode.test.js`, with a fake opencode. Not tried in a real opencode yet.

## Rules

- Proposed (built, 2026-11-11): the default export is a plain `{ id: "clank-talk", setup }`. V2 reads only `id` and `setup()` (opencode docs, Plugins, Support V1), so no `@opencode/plugin` package is needed. Load it with `"plugins": ["<path to clank-talk>/src/js/harnesses/opencode"]` in `opencode.jsonc`; a folder with no `package.json` loads its `index` file.
- Proposed (built, 2026-11-11): `ctx.tool.transform` adds `clank_talk` (JSON Schema input: `script`, `agent`), with `codemode: false`, so no other code calls it around the guard. One ClankTalk session for each opencode session (`context.sessionID`).
- Proposed (built, 2026-11-11): the guard has two walls. A session `context` hook deletes the other tools from each model request. A permission `evaluate` hook denies their actions, with a message that names the AGENTS.talk line. Allowed: `clank_talk`, `question` (the model asks the human), and the names in `allow harness tools`, matched against both tool names and permission actions. The rules are the same as in Claude Code and pi: `require clank-talk`, on by default with an AGENTS.talk, `/clank-talk on|off` for the session. Limit: an action named differently from its tool (for example `edit` for `write`) needs both names in the allow line.
- Proposed (built, 2026-11-11): `ask` with real choices goes through the plugin's own RPC channel (`channel.js`, id `clank-talk`). The server part sends an `ask` event (a random one-time id, the question, the choices, `many`, the session). The TUI part calls `seen` at once, then shows a select dialog (the first choice is chosen at the start), one yes or no dialog for each choice for `with any of`, or a text prompt for no choices, and calls `answer`. Escape is no answer (null). The script's time limit or a stop ends the wait. Each id works once, so an answer for a question that is gone, or a guessed id, does nothing. Security: any client of the local opencode server can call an RPC method and see its events, as it can call opencode's own `permission.reply`; while ClankTalk is on, the model has no shell to reach that server. Not named `rpc.js`, because opencode loads a file of that name as the RPC part.
- Proposed (built, 2026-11-11): if no TUI says `seen` within 2 seconds (a web or desktop client, or an opencode with no RPC), `ask` falls back to opencode's own permission prompt (`ctx.permission.assert`, action `clank_talk_ask`, the question as the resource). Only a question with a yes choice and a no choice: allow gives the first `yes...` choice (else `approve...`), and a deny or a rejection with feedback (a `Tool.Error`) gives `no`. A plain rejection ends the step, as `permission.assert` requires: the tool throws it after the script. Other questions give null (no). The `evaluate` hook always makes `clank_talk_ask` a prompt, so a rule that allows everything cannot answer for the human; a configured deny still wins, which is no.
- Proposed (built, 2026-11-11): `/clank-talk` and `/taint` are in the TUI part, `tui.js`, which opencode loads beside `index.js` (a local folder uses its `tui` file). TUI commands show toasts and dialogs to the human only: no model turn, and the model cannot run them. `/clank-talk on|off` writes `.talk/harness/opencode-<session id>.json` for the open session; the server part reads it for each check (`state.js`). `/clank-talk` with no argument shows a dialog: on or off and why, the allowed names, and the taint. `/taint` shows a select dialog of the inputs that are not approved: Enter or ctrl+o opens the read-only page in the browser, ctrl+a approves the input, ctrl+e approves all; `/taint clear` approves all, with a toast. Why: a server command can only answer with a synthetic message, which starts a model turn. Rejected: the server commands of the first build.
- Proposed (built, 2026-11-11): a `tool.execute.after` hook records each allowed tool in the ClankTalk audit, and `allow untrusted harness tools` makes its result an untrusted input. The event fields (`tool`, `sessionID`, `input`, `status`, `result` or `error`) are checked against the source: `packages/plugin/src/promise/tool.ts`, branch `dev`, 2026-11-11.

## Checked against the source (2026-11-11, anomalyco/opencode, branch dev, @opencode/plugin 2.2.7)

- `Plugin.define` returns its argument, so a plain `{ id, setup }` is the same.
- A tool's `input` can be a JSON Schema (`Tool.ValueSchema`). A result is `{ content: string | Content[] }`. The tool context has `sessionID`, `agent`, `messageID`, `id`, `signal` and `progress`.
- A command gets `{ sessionID, prompt, delivery }`, and `prompt.text` is the typed text.
- `Rpc.define` only checks that no error name starts with `rpc.`, and returns its argument; a method has an `input` and an `output` schema, and event data is an object (`packages/schema/src/rpc.ts`). A TUI part reaches it with `context.client.rpc(definition)`: methods, and `events.on(name, listener)`.
- `ctx.session.synthetic` adds an inbox item, as a user message does, so it starts a model turn. The first build used it for command output; the commands moved to the TUI part for this reason.
- TUI: `keymap.layer` commands with `slash: { name, arguments: true }` get the typed text in `run(input)`; `ui.toast.show`, `ui.dialog.alert` and `ui.dialog.select` (with `actions`: an action does not close the dialog; Enter resolves the selected value; Escape resolves `undefined`); `ui.router.current()` is `{ type: "session", sessionID }` in a session (`packages/plugin/src/tui/context.ts`).
- Code Mode (`execute`) reaches other tools; the guard hides and denies `execute` too, and nested tools keep their own permissions.
